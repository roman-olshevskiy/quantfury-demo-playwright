# v1.0.0 — release notes

Release date: 2026-10-22 · Independent portfolio project, not affiliated with Quantfury.

First complete release of a Playwright + TypeScript test-automation framework for the public
Quantfury demo mode (https://trading.quantfury.com/).

## Highlights

- **Discovery first:** every screen, endpoint, storage key and behavior the tests rely on was
  observed and documented before tests were written
  ([product-discovery.md](../product-discovery.md)).
- **34 tests in four suites:** live HTTP API (18), live UI (7), UI/API integration (3), mocked UI
  (6), plus a cross-browser smoke subset (Firefox, WebKit).
- **Strict TypeScript:** `strict`, `noUncheckedIndexedAccess`, type-aware ESLint with
  `no-floating-promises`; external data is `unknown` until a JSON Schema (Ajv) narrows it.
- **Typed fixtures and isolation:** a fresh demo identity and context per test, immutable data
  shared per worker only, verified on 1, 2 and 4 workers.
- **Consistency checks against the same payload:** integration tests compare the UI with the API
  response that the page itself received.
- **Narrow, schema-validated mocks:** one endpoint per test; expected UI reactions were observed
  before the tests were written.
- **Diagnostics and classification:** redacted, bounded request/response and page diagnostics on
  failure; a pre-flight availability check; CDN block and challenge pages recognized and reported
  as environment failures, never as product defects; slow start-ups annotated.
- **Quality gates:** format, lint, typecheck, live API suite; flaky tests fail the run;
  quarantine only with an issue and a review date.
- **Documentation:** architecture, test strategy, coverage map, reliability results, five ADRs,
  contributing guide.

## Reliability

Repeatability runs on 2026-10-22, no retries, spaced
([reliability.md](../reliability.md#repeatability-runs-v100)):

- live smoke: 5 runs × 6 tests on 2 workers — **30/30 passed on the first attempt**;
- mocked: 10 runs × 6 tests on 4 workers — **60/60 passed on the first attempt** (one slow start
  annotated, not retried);
- CI: static checks and the live API suite (18/18) green on GitHub-hosted runners.

Quality gates were verified with controlled failures (formatting, ESLint, TypeScript, failing,
flaky and expired-quarantine tests, unreachable environment, CDN block pages).

## Known limitations

- **UI suites do not run as CI gates.** On GitHub-hosted runners the Cloudflare layer in front of
  the demo answers the web app's assets with HTTP 403 block pages, so the browser cannot render
  the app ([ADR 0001](../decisions/0001-github-hosted-ci-gates-api-only.md)). Pull requests and
  `main` are gated by static checks and the live HTTP API suite. The live UI, UI/API integration
  and mocked suites are verified locally and run on GitHub-hosted runners only as a non-blocking
  scheduled signal, which reports "environment unavailable" while the block persists. The
  framework does not attempt to bypass the bot protection.
- **WebSocket coverage is transport-level only** (connection, MessagePack handshake, frame flow);
  messages are binary MessagePack and are not decoded.
- **Chart rendering is not verified visually** (canvas in an iframe); chart data is verified
  through the `chart/web` HTTP payload.
- **Start-up stall** in roughly 1 of 15–20 fresh loads (11–17 s) is product behavior; affected
  tests are annotated `slow-start`, not retried.
- **Market- and region-dependent data** (momentum lists, calendars, IP-based country) is checked
  only through rules that hold at any time.

## Not included (next steps, P1)

WebSocket message decoding and reconnect scenarios, sharding with merged reports, Dependabot and a
